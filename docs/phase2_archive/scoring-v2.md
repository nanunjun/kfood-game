# Scoring v2 — 양념 양 연속 판정 + 미각 벡터 + 다인 디너

> 기존 binary(정답/오답) 판정 → **연속/구간 판정**. 코어 리듬 라운드는 유지하되, **양념 양**(리듬 탭 횟수)이 캐릭터 미각 벡터의 최적값에서 멀수록 감점.
> 입력: 캐릭터 미각 벡터·편차(`characters-v2.md`), 재료 티어(`economy-balance-v1.md`).

## 0. UI 표현 원칙 — 숫자는 숨기고, 사람으로 보여준다 (정체성 핵심)
미각 벡터·편차·slot_score·S 등 **모든 수치는 백엔드 계산 전용. 유저 화면에 숫자 노출 0.** 손님의 요구·반응은 전부 **자연어 대사·표정·기분 아이콘·별(1~5)**로만 표현한다.
- **식사 전(요구 힌트)**: 손님 한 문장. 예: 매운맛 높은 손님 → "오늘은 좀 화끈하게요", 단맛 낮은 손님 → "달지 않게 부탁해요", 감칠맛 높은 손님 → "깊은 맛이 좋아요".
- **식사 중/후**: 표정 변화 + 말풍선/이모지(만족 😋 / 그저그럼 😐 / 불만 😖).
- **결과 화면**: 자연어 평가 + 별 1~5 시각화. 예: "딱 좋았어!"(별4~5) / "나쁘진 않아"(별3) / "조금 짰어…"(별2) / "이건 좀…"(별1).

### 0.1 매핑 — 손님 요구 힌트(식사 전): 벡터축 → 한 문장
| 축이 높음(≥0.7) | 대사 예 | 축이 낮음(≤0.3) | 대사 예 |
|---|---|---|---|
| 매 | "화끈하게 부탁해요" | 매 | "안 맵게 해주세요" |
| 단 | "좀 달달하게요" | 단 | "달지 않게요" |
| 짠 | "간 좀 세게" | 짠 | "삼삼하게요" |
| 신 | "새콤한 게 당겨요" | 신 | "신맛은 빼고" |
| 감칠 | "깊은 맛 나게요" | 감칠 | "담백하게요" |
> 가장 치우친 1~2축만 대사화(전부 노출하지 않음 = 캐주얼·탐색감). 까다로운 손님일수록 구체적 요구.

### 0.2 매핑 — 결과 피드백(식사 후): 만족도 S → 자연어 + 별 + 표정
| S 구간 | 별 | 표정/이모지 | 자연어 예 |
|---|---|---|---|
| ≥ θ+0.08 | ★★★★★ | 활짝 😍 | "딱 좋았어! 최고야!" |
| θ+0.03 ~ +0.08 | ★★★★ | 만족 😋 | "맛있었어, 마음에 들어!" |
| θ ~ +0.03 (통과) | ★★★ | 흐뭇 🙂 | "음, 괜찮네." |
| θ−0.10 ~ θ (미달) | ★★ | 애매 😐 | "나쁘진 않은데… 조금 아쉬워." |
| < θ−0.10 (실패) | ★ | 불만 😖 | "이건 좀… 내 입맛은 아니야." |
> **어긋난 축을 자연어로 귀띔**: 실제 입력이 최적보다 짜면 "조금 짰어", 매움 부족이면 "좀 더 매콤했으면". (어느 축이 가장 벗어났는지 → 해당 축 코멘트 1개.) 이게 다음 시도 학습 단서.

### 0.3 별(1~5) ↔ 내부 만족도/통과
별은 표시용. 통과 판정은 내부 θ_pass[level](§5). 별 5단계 = §0.2 구간. (기존 3★ 기록 호환은 §7.)
> 요약: **엔진은 벡터로 계산, 화면은 사람의 말로 말한다.** 디자이너·구현자는 본 매핑을 단일 출처로.

## 1. 양념 양 입력 = 리듬 탭 횟수
- 각 음식은 **양념 슬롯**(seasoning slot) 2~3개를 가짐. 슬롯마다 리듬 탭으로 양을 넣음: **N번 탭 = N단위**.
- 슬롯은 미각 5축 중 하나에 매핑(예: 고춧가루 슬롯 → 매운맛). 탭 단위 범위 `[u_min, u_max]`(보통 0~6).
> 근거: 슬라이더 대신 탭 횟수 = 리듬 게임 코어 유지. 음식별 슬롯 수가 손질→조리→양념 흐름에 자연 편입.

## 1.5 양념 양 입력 UX (직관성)
고BPM·복합 패턴에서 "내가 몇 번 넣었지?"를 없앤다.
- **양념 게이지**: 양념 페이즈 진입 시 하단/측면에 **색깔별 게이지**(고춧가루=빨강·간장=갈색·소금=화이트·설탕=아이보리·식초=연두·육수=황금). 탭/홀드마다 한 칸 + 칸 위 숫자(예: 3/—). 즉시성.
- **양념 노트 차별화**: 일반 리듬 노트와 **다른 색·아이콘**(양념통 아이콘 노트). 종류가 한눈에(상세 `rhythm-variation-v1 §노트`).
- **두 입력 방식**(라운드/음식별 택1):
  - **A. 탭 카운트**(디폴트, 분식 등 빠른 음식) — N탭 = N단위, 게이지 누적.
  - **B. 홀드 노트**(한정식 등 정밀 음식) — 통 누르는 시간 = 양. 길게 홀드 ↑. 정량감.
- **즉시 피드백**: 탭/홀드마다 작은 SFX + 파티클 + 게이지 +1 애니메이션.
- **결과 화면 자연어**: "고춧가루 4단위, 간장 6단위" 표시 → 손님 "조금 더 매콤하게"가 어떻게 반영됐는지 납득(숫자는 결과 복기용, 플레이 중엔 게이지/표정 위주, `§0`).
> 입력 방식 A/B는 음식 데이터 `seasoning_input_mode`(schema-delta 추가 후보). 게이지/노트는 UI 슬롯(`art-needs`, `image_prompts_v2_ui`).

## 2. 캐릭터 미각 → 슬롯별 최적 양
슬롯 `s`(축 `a`, 범위 `[u_min, u_max]`), 캐릭터 벡터값 `v = char.vector[a]`:
```
optimal_units(s) = round( u_min + v · (u_max − u_min) )
```
예: 떡볶이 고추장 슬롯(매, 0~6) · C5 강불(매=0.95) → optimal = round(0 + 0.95·6) = 6 (불맛). C3 조카(매=0.15) → round(0.9) = 1 (순한맛).

## 3. 슬롯 점수 (연속, 편차 적용)
플레이어 입력 `n_s` 탭. **정규화 오차**:
```
e_s = |n_s − optimal_units(s)| / (u_max − u_min)      # 0~1 축 공간
```
캐릭터 편차 `τ = char.tolerance`(정규화, ±0.40~±0.05). **탭 단위 허용폭** = `τ·(u_max−u_min)`.
```
slot_score(s) = clamp( 1 − ( e_s / τ )² , 0, 1 )
```
- e_s ≤ τ → 점수 높음(허용 범위 안). e_s ≫ τ → 0.
- 제곱 falloff = 경계 부근은 완만, 멀어지면 급감(미식가는 한 끗 차이로 추락).

**라운드 raw 점수** (슬롯 가중 `w_s`, 합=1; 디폴트 균등):
```
raw = Σ_s  w_s · slot_score(s)
```

## 4. 재료 티어 부스트 (미식가 통과의 필수 조건)
키 재료의 티어가 만족도에 가산 — 후반 좁은 편차를 상쇄하는 유일한 수단.
| 티어 | 슬롯당 품질 보너스 |
|---|---|
| 기본 | +0.00 |
| 특산품 | +0.05 |
| 명품(브랜드) | +0.10 |
```
qualityBonus = Σ_(키재료) tier_bonus     (상한 +0.20)
S = clamp( raw + qualityBonus + dishwareBonus , 0, 1 )   # 최종 만족도 (그릇 §11)
```
> 근거: raw는 인간 타이밍 오차로 현실 상한 ~0.90. **명품 보너스 +0.10~0.20** 없이는 후반 통과선(θ≥0.92~0.97)에 도달 불가 → "고급 재료로 정밀하게"가 강제됨.

## 5. 통과·별점 (레벨별 임계 θ)
```
Pass(char) = (S ≥ θ_pass[level]) AND (재료 티어 게이트 충족)
```
| Lv | θ_pass | 재료 티어 하드 게이트 |
|---|---|---|
| L1 | 0.55 | 없음 |
| L2 | 0.60 | 없음 |
| L3 | 0.64 | 없음 |
| L4 | 0.68 | 없음 |
| L5 | 0.72 | 없음 |
| L6 | 0.76 | 없음 |
| L7 | 0.80 | 특산품 1+ 권장 |
| L8 | 0.84 | **특산품 1+ 필수** |
| L9 | 0.88 | **명품 1+ 필수** |
| L10 | 0.92 | **명품 1+ 필수** |
| L11 | 0.95 | **전통 명품 필수** |
| L12 | 0.97 | **풀 명품 + 정밀** |
> 별점(보상·기록용): 기존 호환 위해 **3★ ≥0.92 / 2★ ≥0.72 / 1★ else** 유지(아래 §7). 통과 여부는 θ_pass[level]로 별도 판정.

### 5.1 "기본 재료로는 불가" 검증 (L10 평론가 예시)
C13(편차 0.085), θ=0.92. 슬롯 3개 완벽 입력(e_s≈0.03) → slot_score≈1−(0.03/0.085)²≈0.88 → raw≈0.88(완벽에 가까워도 좁은 편차로 1.0 못 미침). 기본 재료(보너스 0) → S=0.88 < 0.92 **실패**. 명품 2슬롯(+0.20) → S=1.0 ≥0.92 **통과**. ⇒ 명품 필수 성립.

## 6. 다인 디너 채점 (레벨 8+)
게스트 g마다 동일 음식의 양념 양으로 `S_g`, `Pass_g` 계산(각자 벡터·편차 다름).
- **[디폴트 A] All-pass**: 전원 `Pass_g` 참이어야 클리어. 표시 점수 = `min_g S_g`(약한 고리). 한 명이라도 미달 = 실패.
- **[대안 B] 가중평균**: `S_party = Σ_g ω_g S_g` (미식가 가중 ω 큼), `S_party ≥ θ_party` 통과. 한 명 미달도 다른 만족으로 보완 가능.
> 디폴트 A 근거: "동시 만족"의 긴장감·전략(중간값 타협 vs 미식가 우선 조준)이 가장 살아남. `[사용자 확인 필요]`

### 6.0 다인 채점 안전장치 — 구조적 무해 보장 (상충 벡터 대비)
극단 상충(극매운 vs 매운 절대불가)이 동시에 와서 **All-pass 수학적 불가**가 되지 않도록 2단계.
- **단계 A — 페어링 규칙(콤보 제한)**: 다인 조합은 **사전 검증된 호환 콤보만** 등장. 캐릭터 짝꿍은 **미각 벡터 코사인 유사도 ≥ 0.85**(상충 강하면 콤보 금지). 예: Junho(매운)×Tae-min(저염) = 짠·매 공통대 OK / Junho×Sunny(단맛 어린이, 매운 불가) = 상충 → 콤보 X. (검증 표 `characters-v2 §3`.)
- **단계 B — 플레이팅 개인 미세 조정(완충)**: 다인은 한 냄비 **베이스** 후, 플레이팅에서 **게스트별 개인 양념·고명 3슬롯**(추가 청양고추/단 양념/새콤 양념/향신 고명) 선택. 점수 = **베이스 매칭 + 개인 조정** 가중.
  | 구간 | 베이스 : 개인조정 |
  |---|---|
  | 캐주얼 다인(L8~9) | 70 : 30 (베이스만 잘해도 통과) |
  | 미식가 다인(L10~12) | 50 : 50 (개인 조정으로 까다로움 보정 필수) |
  - 게스트 g 점수 `S_g = 0.x·base_score + (1−0.x)·personal_score_g`. 개인 조정 슬롯이 상충을 흡수 → 전원 통과 가능.
- UI: 플레이팅 화면이 **게스트 N 분할 그리드**(각 슬롯 = 그릇 + 고명 3종). `image_prompts_v2_ui` 추가 슬롯.
> 결론: 단계 A가 "수학적 불가 조합"을 원천 차단, 단계 B가 "어려워도 길은 있음"을 보장. All-pass 디폴트 유지하되 구조적으로 항상 클리어 가능.

### 6.1 다인 시뮬 예시 (L10, 3인: C13 평론가·C12 셰프·C11 강사 / 떡볶이)
고추장 슬롯(매,0~6) 최적: C13=round(0.55·6)=3, C12=3, C11=3 → 다행히 근접. 설탕 슬롯(단,0~5): C13=round(0.5·5)=3, C12=2, C11=2 → 충돌. 플레이어 단=2 입력 시 C13 e=0.2>편차0.085 → C13 slot_score≈0 → All-pass 실패. ⇒ 단=3 타협 + 명품 보너스로 C12·C11 오차 흡수해야 전원 통과. **타협점 탐색 + 명품**이 핵심.

## 7. 기존 binary와의 호환 / 마이그레이션
현재 라운드: prep(0.20)·method(0.30, binary 정답)·timing(0.50). v2 전환:
- **단계적 블렌딩**: `seasoning_slots`가 없는 음식은 기존 공식 그대로(레거시 모드). 슬롯이 정의된 음식은 v2 공식.
- method binary는 **"조리법 슬롯"**(정답=full, 오답=0)으로 흡수 가능 → 점수 모델 일원화.
- timing(타이밍 바)은 유지하되 가중치를 prep/method/seasoning과 합산. 권장 v2 가중: 손질 0.15 · 조리법 0.15 · 타이밍 0.30 · **양념(seasoning) 0.40**.
- 별점 임계(3★0.92/2★0.72)는 **불변** → 기존 SaveManager 기록·해금 로직과 호환.
> 코드 변경 0(현 단계). 본 문서는 목표 공식·데이터 스키마만 정의. 구현은 후속 sprint.

도구 3티어(기본/프로/마스터, `economy-balance-v1.md §6`). 각 도구가 공식의 특정 항을 보정.
