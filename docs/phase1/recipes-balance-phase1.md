## (b) 밸런스 튜닝값 (Phase 1)
### 판정 윈도우 (half-ms, rhythm-prototype-spec §2)
L1 P±90/G±200 → L8 P±36/G±80. Pro 칼 ×1.3.
### 양념 편차(tol, 정규화) — 레벨=손님 편차
L1 0.40 → L4 0.27 → L8 0.10 (`characters-phase1`). 작을수록 정밀 요구.
### 점수 가중
`S = clamp(0.25·손질 + 0.15·끓이기(hold) + 0.60·양념 + 그릇보너스, 0, 1)`

## (c) M1 통합 매핑 (라운드 일반화)
프로토타입(`rhythm_proto.gd`, 라면 하드코딩)을 **데이터 주도 라운드**로 일반화:
- **MenuRecipe**(메뉴별): seasoning_slots[(id, axis, u_max)] + dishware{best, second, bad} ← 본 (a) 표.
- **Guest**(손님별): taste_vector[5] + tolerance + request_line ← `characters-phase1`.
- **Level**: 윈도우·θ·tol ← (b).
- 라운드 = 손님요구 → 칼질(메뉴 손질재료) → 끓이기/볶기(조리법) → 양념(슬롯) → 플레이팅(그릇 best/2nd/bad) → reveal(메뉴 그릇에 담김) → 자연어 반응.
- 그릇 reveal: 음식별 그릇 모양(양은냄비/뚝배기/돌솥/접시 등)을 그려 **선택 그릇에 담긴 모습** 표시(프로토타입 `_build_vessel` 패턴 확장).
- 데이터 위치: `data-schema-phase1.md`의 FoodDefinition.seasoning_slots / recommended·mismatch_dishware, CharacterDefinition.taste_vector·dialogue.
> M1 작업 순서(build-plan §M1·M2): ① 위 표를 .tres/CSV로 데이터화 → ② rhythm_proto를 MenuRecipe·Guest 읽는 RoundV2로 리팩터 → ③ 12메뉴·5손님 wiring → ④ 그릇/조리 연출 음식별 확장. (엔진 실행은 사용자 머신; 한 메뉴씩 검증하며 확장.)
