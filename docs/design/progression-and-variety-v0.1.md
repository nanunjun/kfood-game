# 구조 재설계 제안 — 메타 progression + 메커닉 다양성 (v0.1 proposal)

> 작성: game-designer/pm · 2026-06-01 · 트리거: 사용자 "선형 난이도 단조로움 / 점수 누적 보상 필요 / 선택+타이밍만 있음 → 다른 게임도 필요"
> 상태: **제안(미확정)** — 사용자 방향 선택 후 spec 확정.

## 1. 현 구조 진단
- 루프: 음식선택 → (장보기 다중선택) → 재료준비(리듬탭) → 조리법(선택) → 타이밍(탭) → 결과별점.
- 문제: ① 메커닉이 **선택 + 타이밍 두 종류뿐** → 음식만 바뀌고 행위는 동일. ② 진행이 **난이도만 상승** → 목표·보상 부재. ③ 별점이 그 판에서 끝남(누적 X) → "왜 잘해야 하나" 동기 약함.

## 2. 제안 A — 메타 progression / 보상 경제 (누적 → 보상)
별점·코인이 **누적**되어 영구적 성장에 쓰이는 메타 루프. 후보 3안:

- **A1. 분식집 키우기 (운영 성장)** — 라운드 별점 → 코인 → **주방 업그레이드(도구 강화 = 판정창 넓어짐, 자동 도움)** + **레시피/음식 해금** + 손님 수·매출 성장. (Cooking-genre 표준, 리텐션 강함)
- **A2. 재료·레시피 해금 트리** — 누적 별 → **다음 단계 재료/음식 해금**(사용자 언급). 요리 "도감" 완성 동기. 단순·명확.
- **A3. 스테이지 맵 + 별 게이트** — 지역(시장→포장마차→한정식) 맵, 별 N개 모아 다음 지역/보스요리/이벤트 해금. Royal Match식 진행감.

> 공통 보상 화폐: ⭐(실력) + 🪙(코인). ⭐로 해금 게이트, 🪙로 업그레이드/소모품. "다음 단계 재료 제공"은 A2/A1에 자연 포함.

## 3. 제안 B — 메커닉 다양성 (조리 행위별 미니게임)
"선택+타이밍" 외에 한식 조리 동작을 **각기 다른 입력**으로. 음식/cut/method에 매핑 → 콘텐츠가 곧 다양성.

| 미니게임 | 입력 | 매핑 (예) |
|---|---|---|
| **드래그 슬라이스** | 재료 위를 손가락으로 그어 썰기(선 따라) | 칼질(채썰기·송송) — 현 리듬탭 대체/병행 |
| **스와이프 말기** | 아래→위 스와이프로 김밥/계란말이 말기 | 김밥(roll) |
| **붓기 게이지** | 누르는 시간으로 적정량 붓기(육수·반죽) | 라면·전·찌개 |
| **휘젓기/치대기** | 원형 드래그 or 연타로 섞기 | 비빔밥(mix)·잡채(toss)·양념재우기 |
| **뒤집기 타이밍** | 스와이프로 전·고기 뒤집기 | 해물파전·갈비(flip, post-launch였음) |
| **재료 받기/순서** | 떨어지는 재료 받기 / 레시피 순서 기억 | 장보기·조립 단계 |

> MVP는 **2~3개 시그니처 미니게임**만 먼저(예: 드래그 슬라이스 + 붓기 + 휘젓기) → 음식별로 골라 배치. 전부 구현은 과함.

## 4. 제안 C — 통합 루프(예시, A2+B 조합)
시장(재료 획득) → **조리 미니게임 2~3개**(음식별 다른 조합) → 서빙/리액션 → **별·코인 누적** → 도감/해금 맵 → 더 어려운/새 음식 + 신규 재료 해금. 난이도는 "상승"이 아니라 **해금으로 새 콘텐츠가 열리는" 느낌.

## 5. 결정 필요 (사용자)
1. **메타 보상 모델**: A1(분식집 운영) / A2(재료·도감 해금) / A3(스테이지 맵) 중.
2. **신규 미니게임 우선순위**: 어떤 2~3개부터.
3. **범위**: 지금 빌드에 점진 추가 vs 구조 문서(GDD) 먼저 재정비.

## 7. 사용자 결정 (2026-06-01)
- **메타 모델 = A2 (재료·도감 해금)** 확정.
- **신규 미니게임 = 드래그 썰기(칼질) + 누르면 붓기 + 휘젓기/치대기** (+ 추가 여지). 별도 sprint로 순차 구현.
- **구현 순서**: ① A2 백본(누적 별/해금/도감) — 완료 → ② 미니게임 3종 순차.

### A2 구현 룰 (v1)
- SaveManager: `total_stars` 누적 + 음식별 `best`(최고 별점). user:// ConfigFile write-through.
- **해금**: 정렬(tier→difficulty) 순서에서 **이전 음식 클리어(별 1+) 시 다음 음식 해금** (sequential). → "다음 단계 음식/재료 제공" 실현.
- **도감**: food_select에 음식별 최고 별점(★★☆) + 상단 누적 별 표시. 잠금 음식은 비활성.
- 결과 화면: 최고 기록 갱신 시 "★ New Best!".
- 후속(B 이후): 별 누적량을 화폐로 한 재료 업그레이드/스킨 등 확장 여지.

## 9. alpha 6차 백로그 (실플레이 피드백)
- **즉시 튜닝(완료)**: 결과 New Best↔리액션 겹침 해소(세로 재배치) / 별점 기준 엄격화(3★≥0.92·2★≥0.72) / 난이도 스프레드 확대(prep 판정창 d별 120→55ms, timing sweep 2.4→0.7s·PERFECT 0.14→0.035).
- **다음 집중 빌드 (한 묶음)**:
  - **#5+#7 prep 재설계 = 드래그 썰기 + 다중 재료**: 단일 재료 리듬탭 → **여러 재료를 차례로 드래그(선 긋기)로 썰기**. 재료별 sprite 필요(art) → 임시는 추상 재료. "다른 게임" + "여러 재료 섞기" 동시 해결.
  - **#3 김밥 roll 미니게임**: roll 음식은 스와이프 말기(아래→위) 연출/판정.
- **art-director 위임(#2)**: 게임 내 **칼/조리도구 전용 스프라이트** + **도마 없는(board-less) 재료 스프라이트** 제작. 현 절차적 칼은 placeholder. 재료 anchor의 baked 도마 때문에 prep 구도 제약 → board-less 재료가 근본 해결.
- **#8 결정 필요 (사용자)**: 조리 타이밍 바 방향 — **가로(현행) vs 세로**. 권고 = **가로**(세로 portrait + 한손 엄지 ergonomics, 좌우 왕복이 탭 타이밍에 자연스럽고 화면 폭 활용). 세로는 "냄비에 내리는" 은유는 좋으나 엄지 정밀 탭 불리.
